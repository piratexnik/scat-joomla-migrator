# AGENTS.md — Інструкції для AI-агентів

Цей документ визначає обов'язкові правила роботи з репозиторієм **scat-joomla-migrator** (SCaT Joomla 1.5 to WordPress Content Migrator).

---

## 1. Економія токенів (Token Efficiency)

- Читати **лише ті файли**, які безпосередньо стосуються поточного завдання.
- **Заборонено** сканувати або читати весь проєкт цілком без прямої команди користувача **«Аудит кода»**.
- Використовувати карту файлів нижче для точкової навігації по проєкту.

---

## 2. Карта файлів (File Map)

- `scat-joomla-migrator.php` — Точка входу, константи, PSR-4 автозавантаження (`ScatMigrator\` -> `includes/`), ініціалізація модулів.
- `includes/Updater.php` — Автооновлення плагіна з GitHub (Public & Private репозиторії).
- `includes/AdminPage.php` — Сторінка адмінки «📦 Міграція Joomla -> WP», діагностика середовища, налаштування токена, інтерфейс пакетного конвертера WebP, мігратора статей та AI-доперекладу.
- `includes/ImageMigrator.php` — Сканер архіву Joomla (`joomla-legacy/images/`, `dmdocuments/`) та пакетний GD-конвертер зображень у WebP (`scat-content-webp/`).
- `includes/ArchiveBrowser.php` — Візуальний провідник «📁 Архів старого сайту» (`Медіафайли -> 📁 Архів старого сайту`) з пошуком, навігацією та імпортом вибраних файлів у Медіатеку WP в 1 клік.
- `includes/DatabaseAnalyzer.php` — Потоковий завантажувач 6 таблиць (`jos_sections`, `jos_categories`, `jos_content`, `jos_languages`, `jos_jf_content`, `jos_docman`) із SQL-дампа Joomla 1.5 та аналізатор структури категорій.
- `includes/ContentMigrator.php` — Пакетний мігратор статей і новин з `jos_content` / `jos_jf_content` у WordPress (гібридний режим `uk_full_plus_existing`, 3-мовні рубрики Polylang, WebP-обкладинки, Rank Math SEO, AI-допереклад через Polyland-Up).
- `assets/admin.js` — JS-логіка AJAX-сканера, пакетної конвертації WebP, аналізатора БД, пакетного імпорту статей та візуального провідника архіву.
- `assets/admin.css` — Стилі сторінки міграції та візуального провідника архіву.
- `DOCS.md` — Технічний паспорт плагіна.

---

## 3. Команда «Аудит кода»

При отриманні від користувача прямої команди **«Аудит кода»** необхідно зняти обмеження на читання та виконати повну перевірку всіх файлів проєкту:

1. **Синтаксис**:
   - `php -l` для всіх `.php` файлів.
   - `node --check` для всіх `.js` файлів (якщо є в проєкті).
2. **Безпека БД**:
   - Усі кастомні SQL-запити мають виконуватися строго через `$wpdb->prepare()`.
3. **Безпека введення/виведення**:
   - Наявність `wp_unslash()`, перевірки Nonce (`wp_verify_nonce()` / `check_admin_referer()`), перевірки прав `current_user_can('manage_options')`.
   - Сувора санітизація вхідних даних (`sanitize_text_field`, `esc_url_raw` тощо) та екранування виводу (`esc_html`, `esc_attr`, `esc_url`).
4. **Стандарти**:
   - Наявність `declare(strict_types=1);` та `defined('ABSPATH') || exit;` у кожному PHP-файлі.
   - Відсутність будь-яких HTTP-запитів усередині фільтра `site_transient_update_plugins`.

## 4. Протокол версіонування та релізів (Формат `X.Y`)

Версія плагіна змінюється **ТІЛЬКИ** за явною командою користувача:

- Команда **«Релиз 2»** (мінорне оновлення / фікс / фіча): збільшити друге число (наприклад, `1.0` -> `1.1`).
- Команда **«Релиз 1»** (глобальний / мажорний реліз): збільшити перше число та обнулити друге (наприклад, `1.2` -> `2.0`).

### Алгоритм релізу:
1. Оновити заголовок `Version:` та константу `SCAT_MIGRATOR_VERSION` у файлі `scat-joomla-migrator.php`.
2. Оновити карту файлів та історію змін у файлі `DOCS.md`.
3. Перевірити синтаксис усіх PHP-файлів через `php -l` (та JS через `node --check`, якщо є).
4. Виконати коміт:
   ```bash
   git add -A && git commit -m "Release vX.Y: <описание>"
   ```
5. Створити анотований тег:
   ```bash
   git tag -a vX.Y -m "Version X.Y"
   ```
6. Відправити зміни та теги на GitHub:
   ```bash
   git push origin main --tags
   ```
